# 09 · 评测与测试

> 前面讲了怎么"造"一个 Agent，这一篇讲怎么"验"它是对的。Agent 测试有个特殊难点：它依赖
> 外部模型，不能每次都真调 API。这里讲怎么"离线"测试。

---

## 一、为什么要测试 Agent

### 1.1 Agent 测试的难点

Agent 由多个部件组成（LLM、工具、循环、上下文），每个部件都可能出错。但难点在于：

- **调真实 API 又慢又花钱**，不能每改一行就跑一遍真模型
- **模型输出不确定**，同样的问题两次回答可能不一样，没法直接断言"结果等于某个固定值"

### 1.2 不测的后果

改了一个工具的代码，结果把 Agent 循环搞崩了，你只有在真实使用时才踩到。更糟的是，
Agent 的错误往往要"多轮、多工具"才暴露，复现困难。

---

## 二、分层测试

把 Agent 拆开，一层一层测，比"端到端一把抓"靠谱得多：

### 2.1 工具层测试

直接测工具函数，不经过模型：

```js
test('calculator 能算四则运算', async () => {
    assert.equal(await runTool('calculator', JSON.stringify({ expression: '(1+2)*3' })), '9');
});
```

- 输入明确、输出明确，最好测
- 重点测：正常情况、边界情况、非法输入

### 2.2 LLM 层测试（mock fetch）

不真发请求，而是**伪造 fetch 的返回值**，测解析逻辑：

```js
test('chat 对 5xx 自动重试，对 401 不重试', async () => {
    globalThis.fetch = async () => new Response('mock', { status: 500 });
    // ... 断言重试了几次
});
```

- 重点测：SSE 解析、重试逻辑、错误分类
- 核心技巧：替换全局 `fetch`，让"网络"变成你能控制的东西

### 2.3 Agent 循环测试（依赖注入）

不调真模型，而是**注入一个假模型**，测循环逻辑：

```js
const fakeModel = async () => ({
    message: { role: 'assistant', content: null, tool_calls: [...] },
    usage: null,
});
const result = await runAgent('x', messages, { callModel: fakeModel });
```

- 重点测：工具结果回填、并行执行、最大轮次、错误隔离
- 核心技巧：让 `runAgent` 接受一个 `callModel` 参数，测试时塞假模型

---

## 三、依赖注入：不调真实 API 测 Agent

### 3.1 什么是依赖注入

**依赖注入（Dependency Injection）**：一个函数不自己创建依赖，而是**由调用方把依赖传进来**。

```js
// 不注入：runAgent 内部直接调 chat
export async function runAgent(input, messages) {
    const msg = await chat({ messages, tools });   // 写死了
}

// 注入：runAgent 接受 callModel，默认是 chat，测试时可以换成假的
export async function runAgent(input, messages, { callModel = chat } = {}) {
    const msg = await callModel({ messages, tools });  // 可替换
}
```

### 3.2 callModel 注入假模型

测试时，传一个"假模型"，它按你的剧本返回：

- 第一轮返回一个 `tool_calls`（假装要调工具）
- 第二轮返回最终回答

这样就能**完全不碰真实 API**，却完整跑通 Agent 循环，验证逻辑是否正确。

## 四、mock 策略

### 4.1 mock fetch

把全局 `fetch` 换成假函数，让"网络请求"返回你预设的响应：

```js
const originalFetch = globalThis.fetch;
globalThis.fetch = async () => sseResponse(chunks);  // 返回预设的 SSE 流
try {
    // ... 测试
} finally {
    globalThis.fetch = originalFetch;  // 记得还原！
}
```

**关键**：测完一定要在 `finally` 里还原，否则会污染其他测试。

### 4.2 假模型

给 Agent 注入一个"按剧本演"的假模型，精确控制每轮返回什么。这样测试是**确定性的**，
不受真实模型随机性的影响。

---

## 五、断言思路

### 5.1 测什么

- **结果对不对**：最终 answer 是否符合预期
- **过程对不对**：调了几个工具、几轮、有没有按预期回填
- **边界对不对**：最大轮次、工具失败、非法输入时的表现

### 5.2 例子

```js
test('agent 执行工具并把结果喂回模型', async () => {
    // 假模型：第一轮要调 calculator，第二轮给答案
    const fakeModel = async ({ messages }) => {
        calls.push(structuredClone(messages));
        if (calls.length === 1) {
            return { message: { role: 'assistant', content: null, tool_calls: [...] } };
        }
        return { message: { role: 'assistant', content: '结果是 5' } };
    };

    const result = await runAgent('算 2+3', [], { callModel: fakeModel });

    assert.equal(result.content, '结果是 5');
    assert.equal(result.stats.modelCalls, 2);   // 调了两次模型
    assert.equal(result.stats.toolCalls, 1);   // 调了一次工具
});
```

注意：这里既断言了**结果**（content），也断言了**过程**（调了几次模型、几次工具）。

## 六、node:test

Node.js 内置了测试框架 `node:test`，不用额外装库：

```js
import test from 'node:test';
import assert from 'node:assert/strict';

test('描述', async () => {
    assert.equal(actual, expected);
});
```

跑测试只需：

```bash
node --test test/*.test.js
```

## 七、代码对应关系

| 概念 | 你的项目 |
| --- | --- |
| 工具测试 | `test/tools.test.js` |
| LLM 测试（mock fetch） | `test/llm.test.js` |
| Agent 测试（依赖注入） | `test/agent.test.js` |
| 依赖注入 | `runAgent` 的 `callModel` / `executeTool` 参数 |

> 说明：这些测试文件在后续重构中引入。当前项目还没有 test 目录。

## 八、小结

- Agent 测试难点：调真实 API 又慢又花钱、输出不确定
- 分层测试：工具层 → LLM 层（mock fetch）→ Agent 循环（注入假模型）
- 依赖注入是"离线测 Agent"的关键，让循环逻辑和真实模型解耦
- mock fetch 测完要在 finally 里还原
- 断言既要看结果，也要看过程（调了几轮、几个工具）
- Node 内置 `node:test`，不用额外装库
