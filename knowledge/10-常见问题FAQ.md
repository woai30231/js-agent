# 10 · 常见问题FAQ

> 出问题时快速定位。每个条目独立成段，便于检索。

## 一、环境与配置问题

### Q1：启动时提示"缺少环境变量 DEEPSEEK_API_KEY"
**原因**：`.env` 文件不存在，或者 key 没填对。
**解决**：复制 `.env.example` 为 `.env`，填入真实的 `DEEPSEEK_API_KEY`。key 一般以 `sk-` 开头。

### Q2：明明在 .env 里写了 key，代码里却读不到
**原因**：读取 key 的模块没有 import `config.js`。`.env` 的加载逻辑写在 `config.js` 顶层，
只有 import 它，`.env` 才会被加载进 `process.env`。
**解决**：确认用到 `process.env` 的文件顶部有 `import { config } from './config.js'`。

### Q3：`node xxx.js` 能读到 key，但别的启动方式读不到
**原因**：`.env` 加载依赖入口模块的副作用。直接用 `node xxx.js` 时，如果 xxx 没经过 `config.js`，
`.env` 就不会被加载。
**解决**：统一从 `config.js` 读配置；或启动命令显式加 `--env-file=.env`。

## 二、API 调用问题

### Q4：返回 401 错误
**原因**：API key 错误或过期。
**解决**：检查 key 是否正确、是否还有额度、是否被禁用。401 属于业务错误，**不要重试**。

### Q5：返回 429 错误
**原因**：请求太频繁，被限流。
**解决**：降低请求频率；如果响应里有 `retry-after` 头，按它等待；否则用指数退避重试。

### Q6：返回 5xx（500/502/503）
**原因**：服务器暂时性故障。
**解决**：这类错误可以**指数退避重试**，通常过几秒就恢复。

### Q7：请求一直卡住不返回
**原因**：没有设置超时。
**解决**：给 fetch 加 `signal: AbortSignal.timeout(60000)`，超时自动中止并抛出 TimeoutError。

### Q8：模型返回"不是合法 JSON"
**原因**：模型偶尔输出半截或格式错误。
**解决**：解析 JSON 时包 try/catch，失败时把它当作"可重试错误"，重新请求一次。

## 三、Agent 行为问题

### Q9：Agent 陷入死循环，反复调同一个工具
**原因**：没有设最大轮次，或 maxTurns 太大。
**解决**：给执行循环加 `maxTurns` 上限（默认 12），到点强制结束并明确告知用户。

### Q10：Agent 编造答案，不调用工具
**原因**：system prompt 没写清"需要真实信息时必须调工具"，或工具描述不清晰。
**解决**：在 system prompt 里明确"涉及时间、文件、计算等真实信息时必须调工具，不要编"。

### Q11：多轮对话后，模型"忘了"前面的内容
**原因**：上下文超过 token 窗口，最早的对话被截断。
**解决**：用截断、摘要、滑动窗口，或"检索增强"（RAG）按需取用历史。

### Q12：某一轮出错后，后续对话全乱了
**原因**：出错那轮的"半截消息"留在了 messages 数组里。
**解决**：失败时回滚——把 messages 长度裁回本轮开始前。

## 四、工具问题

### Q13：模型传的参数是"字符串"而不是对象
**原因**：`arguments` 字段是 JSON 字符串，没做 `JSON.parse`。
**解决**：执行工具前务必 `JSON.parse(call.function.arguments)`。

### Q14：工具结果的 id 对不上，模型张冠李戴
**原因**：回填 tool 消息时，`tool_call_id` 没和调用一一对应。
**解决**：回填时严格携带对应的 `call.id`，并行执行时尤其要结果和 id 绑定。

### Q15：文件工具能访问项目外的文件
**原因**：路径校验用了有漏洞的 `startsWith`，同前缀兄弟目录会被放行。
**解决**：改用 `path.relative` 判断，相对路径以 `..` 开头就拦截。

### Q16：模型删掉了关键文件
**原因**：`delete_file` 没有关键文件黑名单。
**解决**：维护 `PROTECTED_NAMES` 黑名单，删除前检查文件名。

### Q17：抓网页时能访问内网地址
**原因**：没有做 SSRF 拦截。
**解决**：请求前检查主机名，拦截 localhost、127.x、10.x、192.168.x 等内网地址。

### Q18：计算器能执行任意代码
**原因**：表达式直接交给 `new Function` 执行，没做校验。
**解决**：用白名单正则只允许数字和 `+ - * / ( ) .`。

## 五、性能与成本问题

### Q19：token 消耗很高，不知道怎么花的
**原因**：没有统计每轮的 usage。
**解决**：累加每轮模型返回的 `usage`，记录入/出/总 token，必要时看缓存命中。

### Q20：网页/文件内容把上下文撑爆了
**原因**：工具返回超大内容没截断。
**解决**：读文件、抓网页都设置长度上限（如文件 120KB、网页 4000 字符）。

### Q21：回答很慢
**原因**：非流式，要等完整生成才返回。
**解决**：改用流式输出，边生成边显示，感知延迟大幅下降。

## 六、排错步骤清单

遇到问题，按这个顺序排查：

1. **看错误信息**：是网络错误还是业务错误？状态码是多少（401/429/500）？
2. **看日志**：trace 日志里最后一条正常事件卡在哪一步
3. **最小复现**：单独调工具或单独调 chat，排除无关变量
4. **查配置**：key 对不对、模型名对不对、超时和重试参数合不合理
5. **查上下文**：messages 里有没有"断头消息"、有没有超长内容
6. **查边界**：路径沙箱、黑名单、白名单是否遗漏

## 七、小结

- 环境问题：多半是 `.env` 没加载，检查是否 import 了 `config.js`
- API 问题：先看状态码，401/429/5xx 处理方式完全不同
- Agent 问题：设 maxTurns 防死循环，system prompt 防编造，回滚防断头消息
- 工具问题：arguments 要 parse、id 要对应、路径要用 relative 判断
- 成本问题：统计 usage、截断超长内容、用流式提速
